Why

The problem is volume and consistency, not a single good image.

A page is a campaign

A landing page carries a dozen or more visuals. They must read as one set and match how Picsart already looks.

One-by-one does not scale

Hand-prompting each asset is slow and loses the reasoning behind every choice.

The answer is on our pages

Existing pages define the look. The system scrapes them, learns the recurring styles, and reviews new work against them.

How it works

Three parts. Two are deterministic command-line tools. The middle one is a loop of Claude agents.

lp-corpus

1 · Corpus

  • Snapshots live pages with Playwright, media included.
  • Splits each page into typed sections: hero, feature callout, gallery, FAQ.
  • Indexes text and media in SQLite with full-text search.
  • Emits an editable skeleton.md for a new page and pulls similar sections as examples.
/build-landing-page

2 · Build

  • A manager writes one brief per section, with examples and a style family.
  • Workers plan a priced workflow.yaml before spending a credit, then run it step by step.
  • A reviewer scores the asset and the workflow. Rework goes back to the same worker.
  • Hero first, so the rest of the page can anchor to its light and palette.
lp-inject

3 · Inject

  • Writes the chosen media and any changed text into the page snapshot.
  • Uses ids stamped by the corpus tool, so no fragile DOM selectors.
  • Output is a self-contained dist/index.html with its media folder.

The build loop

What happens to one section, from brief to accepted asset.

  1. BriefThe manager copies the section text, its slots, the style family block, two or three corpus examples and the budget line.
  2. PlanThe worker writes every step, model and gate in workflow.yaml, then preflights each paid step for a quote.
  3. Run and gateEach step's output is downloaded, viewed and scored before the next step runs.
  4. ComposeFor composite looks, the worker generates only photo panels. lp-compose draws tiles, pills, frames and labels locally.
  5. ReviewThe reviewer scores fit, resemblance, consistency, cleanliness, artefacts, geometry and legibility. Any model-drawn text is a hard reject.
  6. Rework or acceptRework re-runs from the failing step in the same worker, so upstream results are reused. Accepted slots go into page.md.
brief.md→ workflow.yaml→ steps/→ result.md→ review-1.md→ chosen

Guardrails

Enforced by code, not by instructions, wherever a mistake would cost money or quality.

Credit guard

Paid calls run only on the approved connector, only after a preflight quote, only inside a run, and only under the run cap. A hook denies anything else.

Ledger

Every paid call and every result URL is logged. Spend is reconciled against the account balance after each run.

Output contract

A worker cannot finish until workflow.yaml and result.md exist with the required keys and scores.

Never generated

UI screenshots, icons and decorative brand assets are kept from the source page. Models cannot render product UI faithfully.

No text in images

Copy stays in HTML. Labels and chrome are drawn locally, so the model never has to spell anything.

Style families

Every generated slot names one of seven looks derived from the corpus, so a callout looks like a Picsart callout and not a stock photo.

Style families

Seven recurring ways a Picsart tool page builds an image, found by sampling 700 creatives from the corpus. The corpus is tagged with them by Claude vision.

dark-compositeOne AI result beside tool controls. Model, generator and compare pages.
before-afterTwo panels from one photo. Enhance, upscale, retouch, background change.
crop-frameCrop brackets and a size pill. Resize, crop, expand, social formats.
cutout-checkerboardSubject on a transparency board. Background removal, stickers, product shots.
template-mockupA design card with a photo and a headline box. Template, poster, flyer, logo makers.
prompt-cardPrompt text beside its result. "Type this, get that" heroes and callouts.
full-bleedOne uninterrupted picture. Heroes, gallery tiles and every video slot.

What trial runs taught

  • Section copy alone gives a generic image. The style family, not the text, decides the look.
  • Workers copy the hero composition everywhere unless told that anchoring means light and palette only.
  • Small thumbnails should use the cheaper flash model. Pro fidelity is invisible at that size.
  • The ledger, not the API response, says what was paid.

Decisions that shaped it

Each one is logged with its date and reason in plan.md.

Scrape, do not export
Pages are CMS-driven and client-rendered. No internal export is assumed.
Re-inject, do not template
Writing into a real snapshot gives the highest fidelity. Every new page starts from an existing one.
Workers plan before they spend
A written workflow makes prompts and model choices reviewable, not just the final pixel.
Manager is the main session
Subagents cannot spawn subagents. Messaging keeps a worker's context across rework rounds.
Chrome is drawn, not generated
Tiles, pills and frames come from a local renderer. The model only ever paints photography.
Hooks over instructions
Wrong-connector and unquoted spend are the two mistakes worth making impossible.
